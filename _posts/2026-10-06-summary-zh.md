## [sub2api 曝易支付回调伪造支付漏洞](https://github.com/Wei-Shaw/sub2api/issues/7881) ⭐️ 7.0/10

Wei-Shaw/sub2api 的 issue #7881 报告称，攻击者可复用下单签名伪造易支付（EasyPay）支付成功回调，无需商户密钥即可让未实际付款的充值订单被判定为支付成功。报告指出，任何具备充值下单权限的普通注册账号都能发起该攻击，并已披露完整攻击链与修复建议。 若漏洞被证实，这属于典型的业务逻辑支付漏洞，任何人都可能零成本充值 API 额度，直接给基于 sub2api 的网关运营方造成资金损失。由于 sub2api 是负责计费与配额分发的开源 AI API 网关，使用易支付 popup 模式接入的自建部署是主要受影响群体。 报告将漏洞归因于签名串拼接不转义、return_url 携带的 query 未净化、popup 模式下签名暴露，以及回调参数校验不严格。该 issue 目前仍为 open 状态、尚未验证，作者建议在修复前先切换到非 popup 模式作为临时缓解措施。

telegram · zaihuapd · Oct 6, 13:31

**背景**: sub2api 是一个开源 AI API 网关，用于把 AI 产品订阅转换为可分发的 API 配额，并负责鉴权、计费、负载均衡和请求转发。易支付（EasyPay）是常用的第三方支付聚合接口，通过服务端回调通知商户支付成功。支付回调伪造是一类常见的业务逻辑漏洞，攻击者通过构造虚假的成功通知，让订单在未实际付款的情况下被标记为已支付。
