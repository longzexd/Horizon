GitHub 上 Wei-Shaw/sub2api 的 issue #7881 报告称，攻击者可复用下单时生成的签名来伪造易支付（EasyPay）支付成功回调，从而在不知道商户密钥（pkey）的情况下，让未实际付款的充值订单被判定为支付成功。任何具备充值下单权限的普通注册账号都能发起该攻击，已披露的攻击链影响启用了易支付并采用 popup 模式接入的部署。 这是一个开源支付集成中具体且可操作的支付逻辑漏洞，受影响的部署可能因任意金额的免费充值而遭受直接经济损失。由于该 issue 目前仍为 open 状态、尚待完整验证，运营方应将其视为高优先级预警并立即采取建议的缓解措施。 该漏洞源于签名串拼接未做转义、return_url 携带的 query 参数未净化、popup 模式下签名暴露，以及回调参数校验不严格。issue 作者建议在正式修复发布前，先切换到非 popup 模式作为临时缓解措施。

telegram · zaihuapd · Oct 6, 13:31

**背景**: 易支付（EasyPay）是国内 Web 项目中广泛使用的聚合支付网关：商户服务端先对订单参数（商户 ID、订单号、金额等）进行签名，再把用户重定向到易支付的收银台页面，之后易支付会回传一条带签名的回调来确认支付结果。sub2api 是 Wei-Shaw 的一个开源项目，集成了此类支付流程，其 popup 模式把支付交互嵌入弹窗而非整页跳转。此前 NewAPI 等相关项目也曾报告过类似的易支付签名绕过问题，说明这类集成方式存在反复出现的风险模式。
